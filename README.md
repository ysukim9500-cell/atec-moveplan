# ATEC 이동계획

고객지원사업부 월간 이동계획과 ERP 확정실적을 관리하는 사내 웹 시스템.

팀장 6명이 각자 자기 팀 이동계획을 웹에서 직접 작성하면 사업부 전체 이동계획이 된다.
매주 변동사항은 자동으로 집계되고, 다음 달 초에 나오는 ERP 확정본과 대사한다.

## 구조

빌드 단계가 없다. 정적 파일을 GitHub Pages 로 서비스하고 데이터는 Supabase 에 둔다.
사내 `atecmobility`(통전망 · 차량일지 · 교육 · 장애판단)와 같은 방식이다.

```
index.html      로그인 · 가입 · 2단계 인증
app.html        본체
styles.css      디자인 시스템 — "결산 원장"
mp-auth.js      인증 (Supabase Auth + TOTP)
db/001_schema.sql   스키마 · RLS
```

## 보안

**2단계 인증을 통과하지 않으면 데이터가 한 줄도 나오지 않는다.**

로그인 화면의 장식이 아니라 RLS 조건이다. 모든 `mp_` 테이블의 정책이
`auth.jwt()->>'aal' = 'aal2'` 를 요구하므로, 비밀번호만으로 얻은 토큰으로는
아무것도 읽지 못한다.

그 위에 세 가지가 서버에서 강제된다.

| | |
|---|---|
| 팀장은 자기 팀만 쓴다 | 화면을 조작해도 소용없다 |
| 열려 있는 달에만 쓴다 | 관리자도 예외가 아니다. 먼저 그 달을 열어야 하고 그 행위가 기록된다 |
| 확정된 달은 잠긴다 | 해제하려면 사유를 남겨야 한다 |

읽기는 다르다. 팀장도 사업부 전체 숫자를 봐야 하므로 **읽기는 전 팀 공개**,
쓰기만 팀으로 제한한다.

## 역할

`mp_members.mp_role` — 전사 `profiles.role` 과 별개다.

| 역할 | 범위 |
|---|---|
| `admin` | 전체 수정, 주차 개폐, 월간계획, ERP 업로드, 마감 확정, 팀원 배정 |
| `lead` | 자기 팀만 수정, 전체 열람 |
| `viewer` | 열람만 |

## 데이터

월 축은 연-월 절대 인덱스다. `m = year*12 + (month-1)`, 2026-09 = `24320`.
주차는 0-based (`k=0` 이 1주).

**파생값은 저장하지 않는다.** 합계 · 매출이익 · 영업이익 · 공판 · 사업부합계 · 누적은
전부 화면이 계산한다. 저장하면 반드시 어긋난다.
